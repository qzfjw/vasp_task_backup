# VaspTaskList.md 格式与写入规则

## 列

| 列 | 含义 | 来源 |
|---|---|---|
| 任务ID | 唯一编码，默认 `<前缀>-<yyyyMMdd>-<HHmmss>-<项目名>`，前缀由规则配置 | 自动生成，或 `-TaskId` 指定 |
| 时间 | 服务器本地时间 `yyyy-MM-dd HH:mm:ss` | 写入时由服务器 `date` 生成 |
| 服务器 | 项目所在的服务器：`yang` 或 `lan`（日志文件本身统一在备份主机上） | 项目绑定或显式参数 |
| 任务地址 | 远程任务目录，多个目录用 `<br>` 分隔 | 项目绑定的 source 列表，`$HOME` 在写入时展开 |
| 备份地址 | 本次备份目录 | 备份结果 |
| 使用者 | 提交任务的用户名 | 写入前在项目服务器上取 `id -un` |
| 使用过程 | 这批计算用于做什么图、表或流程 | 用户提供，缺失写“未填写” |
| 计算结论 | 计算结果的核心结论 | 用户提供，缺失写“未填写” |
| 备份校验 | 文件数、大小、SHA256 结果，以及本机目录校验结果 | 备份结果 |
| 备注 | 其他需要保留的信息 | 可选 |

列名集中在 `config/rules/backup-rules.psd1` 的 `TaskLog.Columns`。改列时同时更新本文件。

## 文件结构

文件不存在时创建，内容为标题、说明、`## 备份记录` 和表头；文件已存在且包含表头分隔行时，直接在该表中追加或更新行；已存在但与预期格式不同的文件只追加新的表头和行，不重写原有内容。

单元格内的换行写成 `<br>`，竖线写成 `\|`，避免破坏 Markdown 表格。

## 写入规则

1. 采用“服务器端选择路径 + flock 加锁 + 临时文件原子替换”：先选第一个可用路径，再加锁读改写，最后 `mv` 替换；`mv` 不可用时回退为原地覆盖写入。
2. 同一任务ID再次写入时替换原行，不追加重复行；任务ID不存在时追加到表尾。
3. 写入后立即校验文件中存在该任务ID的行，校验失败时报告且不声称成功。
4. 备份校验不是 `PASS` 时不写日志；`backup_and_log.ps1` 会直接停止。

## 路径选择

`TaskLog.PathCandidates` 默认只有 `/home/bak/VaspTaskList.md`，指的是**备份主机**（`config/servers.psd1` 的 `Common.Backup.Host`，默认 yang）上的路径。yang 和 lan 的项目都登记进这一份日志，靠 `服务器` 列区分。任务地址和用户名会先解析成项目服务器上的真实值（`$HOME`、`id -un`），再写入日志。`/home` 属于 root，普通用户不能直接写到 `/home` 根下，`/home/bak` 必须已存在且可写。按顺序判断：

1. 文件存在且可写，或文件所在目录可写；
2. 文件不存在但所在目录可写。

都不满足时报错并列出尝试过的路径，不自动降级到 `$HOME`，避免日志散落到不同位置。需要改变落点时由用户显式传入 `-LogPath`。
