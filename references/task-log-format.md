# VaspLog.xlsx 格式与增量写入规则

## 工作表与列

- 文件：备份主机上的 `/home/bak/VaspLog.xlsx`
- 工作表：`VaspLog`
- Excel 表格：`VaspLogTable`
- 表头必须严格为：

| 列 | 列名 | 含义 |
|---|---|---|
| A | 编号 | 从 1 开始递增的整数，主键之一 |
| B | 关联任务编号 | 当前任务最近一层任务祖先所包含的直接子任务编号，逗号分隔 |
| C | 操作人 | 源任务目录 owner 的用户名 |
| D | 时间 | 任务关键文件的最新修改时间 `yyyy-MM-dd HH:mm:ss` |
| E | 计算说明 | 化学式、任务类型、关键参数，最多 100 字 |
| F | 使用记录 | 报告/论文文件或可分析性质；不得编造结论 |
| G | 任务所在文件夹 | 源服务器上的绝对任务路径，增量更新的唯一键 |

不要增加“服务器”列来替代路径键，也不要改变列顺序；现有工作簿按此格式维护。

## 更新语义

1. 脚本以 `任务所在文件夹` 查找已有行。路径存在时更新 C-F，保留原编号，不追加重复行。
2. 路径不存在时从当前 A 列最大值加 1，追加到表尾。
3. 不删除当前扫描范围之外的既有行。旧版 VaspLog 中已有但本次不完整/未扫描的任务仍保留。
4. 全部行按路径重新计算 B 列。若新子任务改变了某父任务的直接关联列表，即使父任务内容未变化，B 列也会更新。
5. `关联任务编号` 通过向上查找最近的已登记任务目录得到。只向上找一层父子关系，不把孙任务直接挂到祖父任务。
6. 文件中的重复任务路径视为格式错误，更新直接失败，不猜测保留哪一行。

## 文本类型

`关联任务编号` 必须写成 inline string，并沿用该列原本的文本样式（现有工作簿为 `numFmtId=49`，即 `@` 文本格式）。即使只有一个编号，也不能写成数值单元格，否则 Excel 可能显示为 `2.000...` 或以浮点数参与排序。

`编号` 是整数；`时间` 按现有习惯写为文本；其余列均写为文本。

## 并发与原子性

1. 使用 `/home/bak/VaspLog.xlsx.lock` 和 `fcntl.flock` 获取排他锁。
2. 在内存中读取工作表 XML，修改行列并同步更新：

   - `dimension ref`
   - 表格 `ref`
   - 表格 `autoFilter ref`

3. 先写同目录临时 xlsx，再用 `os.replace` 原子替换。
4. 替换前保留内部备份，默认只保留最近 5 份：`/home/bak/.vasp_task_backup/log-backups/`。
5. 更新后重新打开 zip，校验 XML、表头、任务路径唯一性、新记录存在性和最大编号。

## 依赖边界

登记器只使用 Python 标准库 `zipfile` 和 `xml.etree.ElementTree`，不依赖 `openpyxl`。如果工作表示不是 `VaspLog`、表头不匹配或关键 XML 无法解析，脚本明确失败，不建立另一份 Markdown/CSV 日志作为降级。
